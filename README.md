# Craboard

Windows 上的本地任务看板。单机运行，不依赖账号、网络或云服务；界面基于 Rust + egui，任务存在本机 SQLite。

## 功能

- **四种视图**：今天、全部任务、待办看板、四象限。
- **任务清单**：每个任务可带一组可勾选子项；前置依赖在编辑面板里维护，保存时校验环。
- **时间能力**：截止日期/时间、到期提醒、周期任务（天/周/月/年，可设间隔）。
- **看板约束**：进行中任务数量上限（WIP limit），超限时不能开始新任务。
- **今日进度**：左下角显示今日完成情况，悬停或点击查看明细。
- **便签侧栏**：右侧可折叠，宽度可拖动。
- **外观**：暖夜/暖纸两套低饱和主题，小/中/大三档字号，无边框自绘窗口。
- **运行方式**：普通应用窗口（不置顶、不垫底，出现在任务栏）+ 托盘；可选开机自启；支持全局快捷键。
- **对外接口**：命令行与 MCP（stdio）共用同一套业务规则。
- **试验功能**：AI 总结面板与即时/定时总结，通过程序目录的 `experimental.json` 显式开启，默认关闭。

## 系统要求

- Windows 10 / 11（x64）。
- 构建需要 Rust 1.85 或更高（`edition = "2024"`）和 MSVC 工具链。
- `rusqlite` 使用 bundled SQLite，构建时需要 C 编译器（安装 Visual Studio Build Tools 的「使用 C++ 的桌面开发」即可），运行时不需要额外安装 SQLite。

## 构建与运行

```powershell
cargo build --release
```

产物：

- `target\release\craboard.exe`：图形界面。
- `target\release\craboard-cli.exe`：命令行与 MCP 服务。

图标资源：

- `assets/craboard.ico`：16/20/24/32/40/48/64/128/256 多尺寸图标，`build.rs` 通过 `winresource` 嵌入 exe，供资源管理器、任务栏和快捷方式使用。
- `assets/window-64.rgba`、`assets/tray-32.rgba`：窗口与托盘的运行时图标（裸 RGBA，启动时不用再解码图片）。
- 修改图形后运行 `python tools/make_icons.py` 重新生成（需要 Pillow），再 `cargo build --release`；脚本同时输出 `assets/craboard-256.png` 和 `.probe/icon-preview.png` 预览。

运行：

```powershell
.\target\release\craboard.exe
```

单元测试：

```powershell
cargo test
```

仓库里的 `run.ps1` 是开发辅助脚本：结束正在运行的 `craboard.exe`、重新构建 release、启动并截一张全屏图到 `shot.png`，不参与发布。

## 使用说明

### 窗口与托盘

Craboard 现在按普通应用程序运行：窗口出现在任务栏，参与正常的 z-order，可以最小化或被其他窗口遮挡。

- 标题栏 `—`：隐藏到托盘（进程继续运行）。
- 标题栏 `×`、`Alt+F4`、任务栏关闭：按设置中的「关闭窗口」执行，默认每次询问；选「最小化到托盘」可直接隐藏，选「退出程序」直接退出。
- 关闭确认框中的「最小化到托盘」只隐藏窗口，托盘右键菜单的「退出」始终直接退出，不再询问。
- 托盘图标左键单击：窗口隐藏时立即显示并聚焦；窗口可见时切换为隐藏。
- 托盘图标左键双击：显示并聚焦窗口（不改变已有可见状态）。
- 托盘右键菜单：显示、隐藏、退出。
- `Ctrl+Alt+B`：显示/隐藏切换。
- `Ctrl+Alt+N`：显示并聚焦到「快速添加」输入框。

左键单击与双击共用同一个按键，因此「可见 → 隐藏」会等约 350ms 确认没有第二次点击后才执行；隐藏状态下单击会立即打开，避免等待。双击事件之后系统补发的单击会被忽略，不会把刚打开的窗口又关掉。

窗口位置和大小会记住；如果显示器分辨率变化导致窗口跑到屏幕外，启动时会自动拉回可见区域。

### 任务编辑与时间输入

在列表、看板或四象限中点击任务即可打开编辑弹窗。截止时间使用结构化输入：

- 日期框格式为 `YYYY-MM-DD`，可留空表示没有截止时间。
- 「今天」「明天」「下周一」按钮可直接填入日期。
- 只填日期时按当天 `23:59` 截止，界面会明确提示最终保存值。
- 勾选「指定时间」后，用小时/分钟控件选择时间，范围分别为 `0–23` 和 `0–59`；两个值由控件约束，不会出现 `25:99` 这类输入。
- 支持直接粘贴 `2026-10-21 18:00` 或 `2026-10-21 9:05`，会自动拆分日期和时间。
- 输入内容会实时校验：留空提示无截止时间；合法且未过期时显示绿色「将保存为 …」和相对日期；时间已过用警告色标出；格式不合法时显示红色错误，并禁用保存按钮。
- 周期任务必须设置截止时间；缺少时间时保存按钮不可用。提交时编辑事务还会再校验一次，绕过界面也无法写入非法日期。
- 「+1 天 / +3 天 / +1 周」是快捷延期：周期任务只改本轮，手动修改日期才会移动周期基准。

其他结构化输入（提醒停留秒数、进行中上限、紧急判定窗口）都使用带范围的数值控件，超范围时会自动收敛。

### 快速添加与完整新建

输入框是快速添加：输入内容后回车，直接创建一条今天的普通任务。右侧「＋ 新建」打开完整的创建面板，已经输入的内容会带进面板；在面板里可以设置截止时间、状态、重要性、周期、前置任务和子项，取消时内容还回输入框。

- 快速添加和完整新建走同一套 Core 校验，非法日期、周期缺截止等情况不会写入。
- 同一个面板也用于编辑已有任务；打开面板即可继续增删子项。
- 子项是任务内部的勾选清单，不是独立任务：不设截止时间、状态、重要性、前置或周期，也不单独出现在「今天」、看板或四象限计数里。
- 在列表里可以直接勾选子项，点任务标题左侧的箭头展开/收起清单；完成主任务会把全部子项一并勾选，周期任务完成一轮后子项会重置为未勾选。
- 勾选全部子项不会自动完成主任务；主任务是否完成仍由状态决定。
- 删除任务会连带删除它的子项清单。

### 视图

| 视图 | 说明 |
| --- | --- |
| 今天 | 截止日在今天的任务；没有截止时间的任务按创建日判断。子项跟随主任务显示，不单独占行。 |
| 全部任务 | 所有未完成任务，可切换显示已完成、重要、逾期等筛选。 |
| 看板 | 待办 / 进行中 / 已完成 / 逾期四列，可拖动改状态；窄窗口自动改为纵向堆叠。 |
| 四象限 | 按「重要」和「紧急」划分；紧急判定窗口默认 24 小时，可在设置中调整。 |

看板任务卡片点击可编辑，拖动可改状态。逾期列按截止时间自动归入，不能作为拖动目标。

子项只在所属任务行下展开显示；看板与四象限卡片只显示「子项 x/y」计数，避免卡片内嵌交互与拖动冲突。

### 设置

设置弹窗中可调整：

- 字号（小 / 中 / 大，立即生效）。
- 主题（暖夜 / 暖纸）。
- 时钟是否显示秒。
- 是否开机自启：开启后登录 Windows 时自动启动（正常显示窗口）；只写当前用户的启动项，不需要管理员权限。
- 关闭窗口的行为（每次询问 / 最小化到托盘 / 退出程序）：作用于标题栏 `×`、`Alt+F4` 和任务栏关闭。
- 是否启用截止提醒、提醒停留时长（3–60 秒，鼠标移入后不再自动关闭）。
- 看板的进行中上限（1–99）。
- 四象限的紧急判定窗口（1–720 小时）。
- 打开数据目录。
- MCP 接入：按当前程序的实际路径生成客户端 JSON，可一键复制。
- AI 总结（试验）：仅在 `experimental.json` 开启后出现，见下文「试验功能」。

### 输入法

首次进入输入框时，程序会在检测到文本焦点后主动重新关联一次 Windows IME 上下文，并尽量在启动时把窗口切到前台。部分输入法在窗口第一次获得焦点时只完成窗口激活、没有建立输入上下文，表现为“第一次打不出中文，切一下窗口再回来就好了”；这两步是为了缓解这种情况。若在内网机器上仍然遇到，可先点一下标题栏再点输入框，或切换到别的窗口再切回，并把输入法名称和复现步骤反馈出来。

## 命令行

`craboard-cli` 与 GUI 读写同一份数据，适合脚本、批处理和快速录入。

```powershell
craboard-cli list
craboard-cli list --all --json
craboard-cli add "写周报" --due "2026-10-21 18:00" --important
craboard-cli add "每周复盘" --due "2026-10-23 20:00" --repeat weekly
craboard-cli add "发布 1.2" --subtask "打标签" --subtask-done "回归测试"
craboard-cli edit 7 --due "2026-10-22" --important
craboard-cli edit 7 --subtask "收尾" --subtask-done "复核"
craboard-cli edit 7 --check 2
craboard-cli start 7
craboard-cli done 7
craboard-cli postpone 7 --by 2d
craboard-cli settings --wip-limit 5
craboard-cli data-dir
```

常用命令：`list`、`show`、`add`、`edit`、`done`、`start`、`postpone`、`remove`、`settings`、`data-dir`、`mcp`。完整参数见：

```powershell
craboard-cli help
```

约定：

- 截止时间：`2026-10-21 18:00` 或 `2026-10-21`；只给日期按 `23:59`。
- 周期规则：`daily`、`weekly`、`monthly`、`yearly`，也可用间隔写法如 `2d`、`3w`。
- 顺延时长：`1d`、`3d`、`2h`、`1w`；纯数字按天。
- 子项：`--subtask` 添加未勾选子项，`--subtask-done` 添加已勾选子项，均可重复；`edit` 传入任一个会整体替换清单，`--clear-subtasks` 清空。单点勾选用 `--check <序号>` / `--uncheck <序号>`，序号从 1 开始。
- 加 `--json` 输出机器可读结果，包含 `created_at` / `updated_at` / `completed_at`。
- 总结相关选项（`--ai-summary`、`--ai-daily`、`--ai-daily-times`、`--ai-interval`、`--ai-summary-hours`）只在 `experimental.json` 开启 `ai_summary_active` 时可用，`--json` 也只返回已开放的设置字段。
- CLI 每次操作都会重新打开存储，GUI 会在约 1 秒内自动重载外部改动。

## MCP

启动 stdio MCP 服务：

```powershell
craboard-cli mcp
```

客户端配置示例（把路径换成实际构建位置）：

```json
{
  "mcpServers": {
    "craboard": {
      "command": "D:\\Code\\craboard\\target\\release\\craboard-cli.exe",
      "args": ["mcp"]
    }
  }
}
```

实际使用时不必手填路径：设置 →「MCP 接入」会按当前 `craboard.exe` 所在目录生成整段 JSON，点「复制 JSON」后合并到客户端的 `mcpServers` 并重启客户端即可。移动程序目录后需要重新复制。

服务使用换行分隔的 JSON-RPC 2.0（每条消息一行），协议版本 `2024-11-05`，不依赖 GUI 进程运行。

提供的工具：

| 工具 | 作用 |
| --- | --- |
| `list_tasks` | 列出任务，支持未完成/重要/逾期/截止窗口/关键字筛选。 |
| `get_task` | 读取单个任务的完整信息，含子项清单与完成数。 |
| `add_task` | 新建任务，可带截止时间、重要标记、周期规则、子项清单和前置任务。 |
| `update_task` | 修改指定字段；显式传 `null` 可清空截止或周期。`subtasks` 传数组整体替换，`null` 或 `[]` 清空。 |
| `set_subtask_done` | 勾选或取消单个子项；`index` 从 1 开始，全部勾选不会自动完成主任务。 |
| `complete_task` | 完成任务；周期任务推进到下一轮并返回 `next_due`。 |
| `start_task` | 标记为进行中，受 WIP 上限约束。 |
| `postpone_task` | 按 `by` 或 `to` 推迟。 |
| `delete_task` | 删除任务并清理引用。 |
| `get_settings` | 读取设置。 |
| `update_settings` | 修改设置，数值自动收敛，每日定点时间排序去重。 |
| `get_ai_summary` | 读取总结状态与调度配置（试验）。 |
| `set_ai_summary` | 写入外部生成的总结正文（试验）。 |
| `clear_ai_summary` | 清除已保存的总结（试验）。 |

`subtasks` 既可以传字符串数组（未勾选），也可以传 `{ "text": "...", "done": true }` 对象数组。例如 `add_task` 的 `arguments` 可写成 `{"text":"发布 1.2","subtasks":["打标签",{"text":"回归测试","done":true}]}`。

> `get_ai_summary`、`set_ai_summary`、`clear_ai_summary` 属于试验功能，只在 `experimental.json` 开启总结面板后才出现在 `tools/list` 中；关闭时 `get_settings` / `update_settings` 也不暴露总结字段。

## 试验功能

试验功能默认全部关闭，通过程序目录（`craboard.exe` 与 `craboard-cli.exe` 所在目录）的 `experimental.json` 开启。文件不存在等同全部关闭；发布包中两个 exe 同目录，只需维护一份配置。

```json
{
  "ai_summary": true,
  "ai_summary_active": false
}
```

| 字段 | 作用 |
| --- | --- |
| `ai_summary` | 在左下角「今日进度」悬浮页显示今日总结，并开放 MCP 的 `get_ai_summary` / `set_ai_summary` / `clear_ai_summary`。 |
| `ai_summary_active` | 开放「即时总结」按钮与每日定点/固定间隔两种定时总结（含设置页、CLI 和 MCP 字段）；开启时自动包含 `ai_summary`。 |

使用方式：

- 程序不内置模型，也不读取 API Key。总结正文由用户自己的 AI 助手通过 MCP 推送：agent 先调用 `get_ai_summary` 读取可用性、正文和生成时间（开启主动总结时还包含下次触发窗口），再结合任务情况把生成的正文用 `set_ai_summary` 写回。
- 只开 `ai_summary`（推荐先这样用）：悬浮页只显示 agent 推送的正文，不显示「即时总结」按钮，也没有定时配置；正文为空时提示等待推送。
- 开启 `ai_summary_active`：设置页出现「AI 总结（试验）」分区，可配置总开关、每日定点（可多个时间点，窗口为当天 `00:00` 到触发时刻）和固定间隔（窗口从上次任意来源的总结起算）。「即时总结」按钮由程序按当前任务现场生成文本，不调用模型。
- 修改配置后需要重启程序：GUI 在启动时读取，MCP 服务进程在启动时读取（重启 MCP 客户端或其中的 craboard 服务即可），CLI 每次调用时读取。
- 配置按 JSON 解析，缺省字段为 `false`；读取或解析失败时全部按关闭处理，GUI 启动时弹提示并写入 `crash.log`，不影响正式功能。
- 悬浮页和设置页的总结入口只在开启后出现；关闭时界面与普通版本一致，仅在左下角显示今日完成情况。

## 数据与备份

数据目录默认为 `%APPDATA%\craboard\`，可用 `craboard-cli data-dir` 查询。

| 文件 | 说明 |
| --- | --- |
| `tasks.db` | 任务主存储（SQLite，WAL 模式，schema v4，含创建/更新/完成时间与子项清单）。 |
| `state.json` | 窗口位置/大小、视图、主题、字号、设置、便签、总结状态。 |
| `tasks.json` | 仅在 SQLite 打不开时启用的兜底存储。 |
| `state.json.before-sqlite` | 任务迁移到 SQLite 前的旧 JSON 备份（首次迁移时生成）。 |
| `crash.log` | 托盘、快捷键、存储等非致命错误日志。 |

说明：

- 任务 ID 由存储层分配，删除后不复用。
- 设置写入采用「临时文件 + 替换」，避免中途崩溃留下半截 JSON。
- 任务写入只同步发生变化的行，并在事务中提交。
- `created_at` 在新建时写入；`updated_at` 在编辑、改状态、延期时更新；`completed_at` 在完成时写入，取消完成后清空。周期任务完成一轮只推进截止时间，不算任务完成。
- schema v3 迁移时，旧任务用创建日补 `created_at` / `updated_at`（00:00）；旧已完成任务没有可还原的完成时间，`completed_at` 保持为空。
- schema v4 增加 `subtasks` 列。旧版本的父子任务会在加载时合并：所有后代任务按 ID 顺序转成根任务的勾选子项，子任务行随后删除；新的写入不再使用 `parent` 列。
- 备份时直接复制整个目录即可；恢复前请先退出 Craboard。

## 项目结构

```
src/
  main.rs           GUI 入口：窗口、托盘、全局快捷键、自动保存
  win32.rs          少量 Win32 调用：窗口样式、可见性、屏幕边界、开机启动项
  state.rs          数据模型、日期解析、设置读写与规范化
  storage/          TaskStore 抽象、SQLite / JSON / 内存后端
  core/             业务规则：任务增删改、状态迁移、周期、视图投影、总结调度
  ui/               egui 界面：board / kanban / settings / reminder / theme
  mcp.rs            stdio MCP 服务
  bin/craboard-cli.rs  命令行入口
```

更详细的分层、数据流和设计取舍见 [DESIGN.md](DESIGN.md)。

## 已知限制

- 仅支持 Windows：托盘双击、无边框窗口和屏幕边界处理依赖 Win32。
- 单用户、本地存储，没有同步和多人协作。
- 没有撤销栈；删除任务前请确认。
- 开机自启记录的是启用时（或最近一次启动并开启自启时）的 exe 路径；移动程序后在新位置手动启动一次即可自动修正。
- GUI 与 CLI/MCP 同时高频写入时以最后一次提交为准；日常使用（GUI 前台、外部偶尔写入）没有问题。
- 直接手改 `tasks.db` 不受支持；需要脚本化修改请走 CLI 或 MCP。
- 输入法兼容性仍取决于系统 IME：开发机只验证了微软拼音，内网第三方输入法未覆盖；若首开仍打不出中文，请参考「输入法」一节的操作并反馈复现信息。
- 「今日完成」仍按任务的今日相关性（今天到期，否则按创建日）统计，不按 `completed_at` 统计；两者在跨天完成/提前完成时可能不一致。
